## 0. 一页摘要

| 维度 | v4 | v5 | 变更理由 |
|---|---|---|---|
| 状态机制 | 7 个状态永久累积，越玩越脆/越强 | 7 个状态带**时长**（2-3 回合）自然消退 | 永久累积 = 后半程数值失真，且玩家看不懂「为什么突然掉」 |
| 状态触发 | 必触发 | **概率触发**（基准 50%-70%，工程侧全局再 ×0.4） | 必触发让状态变成"必修课"，概率化才有"这次翻车了"的意外感 |
| 状态说明 | 只有名字 | 每个状态一句 ≤30 字**侧栏说明 + 时长** | 需求：玩家看到状态名要立刻明白含义与还能撑多久 |
| 负面状态 | 3 个（夜猫子 / 情绪化 / 破潜） | 3 个（**破防 / 社死 / emo**），全部绑定声望/人际下跌 | 形成"说错话 → 掉人际 + 挂状态"的代价链 |
| 事件总量 | 59 | **67**（删 4、增 12） | 情感向扩增 + 净化不合情境内容 |
| 重复触发 | 5 个 repeatable，多出 11 次额度 | **0 个**，全部单次 | 需求：一个事件只该经历一次，重复会打破"这是真发生过的事" |
| 图鉴 | 只有名字 + 描述 | 12 结局 + 12 成就各补一句**触发条件**，已解锁才展示 | 需求：让玩家知道"我还能解锁什么"，但不剧透 |
| 开局微调 | 单属性上限、未限总量 | **合计 5 点自由分配** | 给玩家一点"这是我捏的人"的掌控感 |

数据规模：**67 事件 / 248 选项 / 65 个沉默选项 / 90 个选项会挂状态（78 正向 + 12 负向）**。
全部 67 段通过 `ChatImporter.validateEvent` 与自写契约校验（`ALL CHECKS PASSED`）。

## 1. 状态体系 v5（7 个）

### 1.1 设计动机

v4 的状态是「计数器」：进状态就永久 +1，工程侧用 `requires.states` 数个数当钥匙。
两个问题：

1. **数值失真**：一局 25 段下来，玩家身上挂着七八个状态，后期所有判定都在"我有 5 个正面状态"的地基上跑，数值曲线变成单调上升或单调崩塌。
2. **玩家不可读**：状态栏是一排甩不掉的名词，玩家既不知道它什么时候走，也不知道它具体在做什么。需求原话是「玩家看到状态名能立刻明白含义与持续时间」。

v5 把它改成**短时状态**：进来、影响 2-3 个回合、自然退去。代价是它不能再当结局门槛（终局残留是随机的），所以 **v5 的结局判定彻底改用「终值 + 剧情印记 flag」**（见 §4.1）。

### 1.2 状态表（`GAME.STATES_META`）

| 图标 | 名称 | 正负 | 时长 | 侧栏说明文案（≤30 字） | 投放选项数 |
|---|---|---|---|---|---|
| 🔥 | 上头 | good | 3 回合 | 一冲动就敢接话、敢起哄，三个回合后自然退去 | 28 |
| 🍉 | 瓜瘾 | good | 2 回合 | 群里一有热闹就想围观，两个回合内坐不住 | 20 |
| 📚 | 卷王附体 | good | 3 回合 | 一头扎进学习，效率高但人也绷得紧，持续三个回合 | 23 |
| 💪 | 薄肌之魂 | good | 2 回合 | 想去操场和健身房，自律的自信还在，持续两个回合 | 9 |
| 💔 | 破防 | bad | 3 回合 | 心态被戳中了，三个回合内一句话就能让你难受 | 2 |
| 😳 | 社死 | bad | 3 回合 | 刚在全群面前翻过车，三个回合内说话容易被玩梗 | 4 |
| 🌧 | emo | bad | 2 回合 | 深夜情绪上头，想找人说话又不敢，持续两个回合 | 6 |

取舍说明：
- **保留 4 个 v4 正面状态**（上头 / 瓜瘾 / 卷王附体 / 薄肌之魂），只补时长与文案，事件链与 flag 不受影响。
- **换掉 v4 的夜猫子 / 情绪化 / 破潜**：这三个是"长期人设"型状态，和"2-3 回合的短时状态"语义冲突（"破潜"更是 flag 性质）。改由 `破潜` / `潜水大师` 等 flag 承担，状态栏只放短时情绪。
- **新增 3 个负面状态**：破防（被戳中）、社死（当众翻车）、emo（深夜情绪），全部来自真实群聊里反复出现的情绪场景。
- 总数 7 个，落在需求要求的 5-7 区间；`duration` 全部 2-3 回合。

### 1.3 生命周期与判定语义（工程侧契约）

数据层只提供 `duration` 与 `kind`，运行时由 `engine.js` 实现：

```
进入：states[name] = { count: 1, remaining: duration }
每回合结束：所有状态 remaining -= 1；remaining <= 0 则整条移除
同名再次进入：count += 1 且 remaining 重置为 duration（不叠加时长）
requires.states 判定：只看"当前仍有效"状态的 count
```

要点：
1. **重置而不是累加时长**——否则反复触发会让状态无限延长，等于回到 v4 的永久态。
2. **count 保留**——v4 有事件用 `requires.states: { '夜猫子': [3,99] }` 这种"攒够几次"的钥匙；v5 语义下这类门槛已全部改写成 flag（见 `ev_nightowl` → `夜猫子` flag 移除，改用 `破潜` / `深夜真心话`）。
3. 状态不得作为结局门槛（`match.states` 子句在 `EndingResolver` 里保留兼容，但 12 条结局均未使用）。

### 1.4 触发概率设计

契约：`effects.stateChance` 是**基准概率**，工程侧统一再乘全局系数 **0.4**。
即玩家实际看到的状态触发率 = `stateChance × 0.4`。

| 基准 stateChance | 选项数 | 实际触发率 | 使用场景 |
|---|---|---|---|
| 0.50 | 16 | 20% | 负面状态（破防 / 社死 / emo）——翻车要"有时会"，不能"一定" |
| 0.55 | 35 | 22% | 普通正向状态、需要克制的冲动类 |
| 0.60 | 33 | 24% | 典型行为（发图、接话、开黑） |
| 0.65 | 5 | 26% | 强行为（去健身、上台） |
| 0.70 | 1 | 28% | 唯一一处"拉满引体向上"，高光时刻必挂一点 |

规则：**凡带 `states` 的选项必须显式写 `stateChance`，不允许留默认 1**（已用脚本全量校验）。
一局 25 段里，期望进入正面状态 5-7 次、负面状态 1-2 次——这个强度是刻意的：负面状态是"调味"，不是"主线"。

### 1.5 负面状态选项清单（12 条）

### 2.3 全部单次触发

`repeatable` 字段在 67 个事件中**零残留**（脚本硬校验）。
v4 的 5 个 repeatable（`ev_water` / `ev_bubbletea` / `ev_express` / `ev_cat` / `ev_lerun`，共多出 11 次触发额度）改为单次；其中 `ev_cat` 直接删除，另外 4 个靠 §2.1 的后移来补足池子长度。

副作用与对策：单次化后可用事件少了 11 个额度，25 回合更容易"抽空"。对策是把 10 个高频日常梗后移到 53-62 当长局填充——它们被抽到的概率低，但一旦抽到就是新增内容，不会出现"同一件事做三遍"。

### 2.4 群聊情境净化

净化标准（三条，任一不满足即改写或删除）：

1. **有他人在场**：事件必须发生在群里，或者"你在群里发言 / 被 @ / 看别人发言"。单人线下的内心独白不算。
2. **有共同观众**：选择的后果要有人看见（群友的反应、复读、接龙、截图）。只影响自己的选择等于没有社交压力。
3. **可被引用**：正文里最好有一句"能被人复读的原话"——这是这个群的真实语法。

按此标准执行的改写（举例）：

| 事件 | v4 写法 | v5 写法 | 净化的点 |
|---|---|---|---|
| ev_morning | 你起床去上早八 | 群里复读「起来上早八的人有福了」，你在队形里选站位 | 从"我的早晨"变成"群里的接龙仪式" |
| ev_library | 你去文图自习 | 群里在抢座接龙、有人发空座照片 @ 全体 | 从"我的学习"变成"公共资源争夺" |
| ev_run | 你一个人去跑步 | 群里约跑、发定位、互相打卡 | 从"我的锻炼"变成"约不约" |
| ev_pe | 你体测跑一千米 | 群里开直播帖实时更新战报，有人在倒数 | 从"我的成绩"变成"当众表演" |

### 3.2 素材筛选方法

1. 解析 `聊天记录.txt`（约 50 万行 / 12.1 万条），只取 `[..] [..] [文本]` 块且剔除含 `<>` 的引用转载块，得到 **74373 条**纯文本消息，建索引 `[时间, 发言人, 正文, 全局序号]`。
2. 按情感关键词统计命中量：喜欢 486 / 朋友 388 / 哭了 357 / 恋爱 164 / 对象 124 / 谈恋爱 91 / 妈妈 66 / 暧昧 51 / 暗恋 25 / 异地 25 / 表白 22 / 分手 21 / 脱单 19 / 孤独 14 / 前任 13 / 抱抱 13 / 白月光 12 / 相亲 11 / emo 5 / 催婚 4 / crush 3。
3. 按"命中密度 + 上下文可读性"挑出 12 个场景原型，回溯命中的上下文窗口（`rng.py a b` 拉整段对话），确认有 3 人以上参与的群内对话才采用。
4. 单条原话直接进正文，多人对话压成 1-2 句"群友的发言"，避免生造。

**只有一条线没有完全落实**：`crush` 命中仅 3 条，`ev_crush_speaks` 的"TA 在群里说话了"这个具体情境是**根据暗恋话题的口吻推演的**，不是直接抄某一条记录。其余 11 段都有明确原话锚点。

### 3.3 为什么不做成私聊

原始素材里有大量一对一私聊感的内容（"我跟我妈打电话""他说他要分手"）。全部按 §2.4 的标准改造成群内发言：

- **改成"当事人自己在群里说"**：分手小作文、冷战、被拒，都是本人发在群里的长文，玩家是围观者/接话者，而不是被私聊的对象。
- **改成"接龙/复读"**：想家、下雪、失眠，用群友排队的语法，避免变成"我一个人的深夜"。
- **沉默选项保留但必须"被看见"**：如 `ev_crush_speaks` 的"把这段聊天截了图"——不说话，但做了一个有后果的动作。

v4 的均值是 16.6，v5 抬到 19.3——因为"有涨有跌"的硬约束让每个选项都得多带一个负项（v4 有 79 处 `energy: -1/-2/-3` 这种几乎无感的消耗，v5 全部删除后改由一次到位的 `-3 ~ -9` 承担）。p90 = 25 说明绝大多数选项仍在"能感知但不致命"的区间。

## 6. 开局微调改成 5 点自由分配

`GAME.CONFIG` 新增 `adjustPoints: 5`，并更新 `adjustRange` 注释：

```
adjustStep: 1,        // 微调步长
adjustRange: 5,       // 单属性微调上限 5、全属性合计 5 点
adjustPoints: 5,      // v5 新增：开局可自由分配的总点数
adjustCap: { relation: 85, mood: 85, fame: 85, energy: 90 },
```

语义：玩家在选角后有 5 点可自由分配到四项数值上，单属性最多 +5，合计必须正好分完 5 点；`adjustCap` 是硬上限兜底（防止微调抹平角色差异，例如 memedealer 的 relation 63 + 5 = 68 < 85 不受限，但高基础值角色会被 cap 卡住）。
工程侧需在选角界面做"剩余点数"显示与"未分完不允许开局"的校验。
